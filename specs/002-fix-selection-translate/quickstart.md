# Quickstart: 划词翻译体验修复与增强

## 前置条件

- Node.js 20+
- pnpm 9+
- Chrome 或 Edge 浏览器
- 已配置硅基流动 API Key

## 安装与开发

```bash
pnpm install
pnpm dev
```

加载扩展：

1. 打开 `chrome://extensions`
2. 开启「开发者模式」
3. 选择 `.output/chrome-mv3-dev` 加载未打包扩展

## 自动检查

```bash
pnpm test
pnpm build
```

建议覆盖的单元测试：

- `lib/selection.ts`: 1000 字符上限、纯标点/空白、词典/翻译模式、当前句子提取
- `hooks/useLookupStream.ts`: 旧 requestId/selectionId 消息不会更新当前状态
- `lib/richText.ts`: 允许标签/样式保留，脚本、事件属性、远程资源、未知类被移除
- `lib/siliconflow/parser.ts`: `contextMeaning`、`pronunciation`、`richHtml` 的兼容解析

## 手动验证场景

### 场景 1：新选区不复用旧结果

1. 打开英文文章页
2. 选中 `apple` 并触发翻译
3. 不刷新页面，选中 `network` 并触发翻译
4. 预期：最终可见结果只对应 `network`，不会显示 `apple` 的释义
5. 预期：如果 `apple` 请求稍后返回，不会覆盖当前弹框

### 场景 2：图标每次新选区都出现

1. 连续选择页面上 5 个不同单词
2. 每次关闭弹框后再选择下一个单词
3. 预期：每次有效新选区附近都出现翻译图标
4. 预期：快速切换选区后页面只保留最后一个选区的图标

### 场景 3：长文本可完整阅读

1. 选择 200-1000 字符文本
2. 触发翻译
3. 预期：原文默认收起，译文区域可滚动查看完整结果
4. 展开原文
5. 预期：原文过长时也可滚动，并可再次收起

### 场景 4：超过 1000 字符

1. 选择超过 1000 字符文本
2. 预期：不发起翻译请求
3. 预期：显示“选区过长，请缩小范围”一类提示

### 场景 5：单词发音播放

1. 选中英文单词 `welcome`
2. 触发词典模式结果
3. 预期：结果卡片出现播放按钮
4. 点击播放
5. 预期：可听到发音；若浏览器/系统不支持，显示不可用状态且释义仍可阅读

### 场景 6：当前句子中的意思

1. 在句子 `She built a strong network in the industry.` 中选中 `network`
2. 触发查词
3. 预期：结果包含“在当前句子中的意思”，说明这里偏向“人脉关系”
4. 在无法提取完整句子的页面区域重复
5. 预期：仍展示通用释义，并提示上下文解释受限

### 场景 7：渐进式富文本展示

1. 选择较长句子或短段落
2. 触发翻译
3. 预期：首批可读内容在完整结果结束前出现
4. 预期：已出现内容排版清晰，后续内容继续增量更新
5. 预期：弹框样式不影响原网页

### 场景 8：不安全生成内容降级

1. 使用测试桩或模拟响应返回包含 `<script>`、事件属性、远程图片或未知 class 的片段
2. 预期：危险内容被移除
3. 预期：清洗后为空时降级为纯文本或错误态，页面不报脚本错误

### 场景 9：错误恢复

1. 填入无效 API Key
2. 触发翻译
3. 预期：弹框显示可理解错误
4. 修正 API Key 后重新选词
5. 预期：图标重新出现，翻译结果正常展示

## 完成标准

- P1 三个问题均可复现验证通过：最新选区结果、图标重复出现、长文本完整阅读
- 发音播放入口和失败态均可验证
- 当前句子语境释义只发送选中词和当前句子
- 渐进式富文本内容经过清洗后展示，不污染宿主页
- `pnpm test` 和 `pnpm build` 通过
